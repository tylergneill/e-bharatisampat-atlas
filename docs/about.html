About

ebharatisampat.in ("ई-भारतीसम्पत्") is a digital Sanskrit library by Samskrita Bharati, started in 2017.

This unofficial “atlas” interface — not affiliated in any way — offers a better way to explore the contents of this vast and underestimated collection. It is an "atlas" in the sense that it not only charts the navigable waters — with more transparent browsing by category and author — but also plumbs their depths — with visibility into sizes, counts, and changes over time that the source collection doesn't surface on its own. It is not a mirror, as it hosts no text of its own; instead, every entry links back to ebharatisampat.in for the actual content.

For more perspective on this and sibling Atlas projects, see Sāgarasaṅgama.

Data last sourced is the last time every text was fetched in full, which is what the sizes are measured from. Data pipeline last run is the last time the Atlas was rebuilt, which can add newly listed items and their metadata between full fetches.

Practical Intro to E-bharatisampat Structure

Two Overlapping Collections: Searchable Texts and PDFs

Ebharatisampat.in holds 11,212 distinct items as indicated by "serial" number. These items contain either searchable text (shelved as "Unicode Books" if proofread, "AI-converted books" if not), a PDF ("E-Books"), or both. Every "AI-converted" item (1,364) also has a PDF and shows up under "E-Books," but only 2,597 of 4,242 "Unicode Books" do.

AI-converted Books

Of the items with both searchable text and a PDF (3,961), 1,364 have text that has not been proofread. The site calls these "AI-converted books" and lists them on their own shelf and under "E-Books," but not under "Unicode Books." So browsing "Unicode Books" alone undercounts the searchable text on the site.

Until the site was rebuilt in November 2026, these items had no shelf of their own. They appeared only under "E-Books," so finding them as texts took luck.

Multiple Editions of One Work

The collection is a library of printed editions, not a canon of works, so repeated titles are expected rather than duplicates to be merged. There are over thirty काव्यप्रकाशः items here, nearly thirty of हितोपदेशः, and so on.

Metadata

Each item has a metadata page (URL readSearch.php), e.g., this कादम्बरी. These pages are the most basic representation of an item, containing all available metadata, plus some number of content links depending on available data type: "Read Unicode" or "Read Chapter" if it has searchable text (see Structured vs. Unstructured Texts below for the distinction), and/or "Read E-Book" if it has a PDF.

Structured vs. Unstructured Texts

Of the searchable e-texts, some (666) are furnished with chapter-by-chapter structure. On the source website, these are accessed via "Read Chapter" links, where the interface (URL read_chapter) presents text with a clickable table of contents (under "Title" in the "Note Book" sidebar, which is hidden by default).

By contrast, the vast majority of searchable e-texts (4,940) are accessed via "Read Unicode" links, whose interface (URL readbook3) presents text that is unstructured, with no table of contents.

Either type can be downloaded in full only if logged in as a registered user.

Categories and Authors

With very few exceptions, every item is classified with both a top-level category (also "domain") and a subcategory ("subdomain"). Each subcategory belongs under exactly one category. That means that categories form a clear tree structure, and each item sits in exactly one place in that tree.

Approximately 65% of items have a non-empty author. This naturally divides by genre: Only 15% of items in उपनिषदः have an author. By contrast, 82% of साहित्यम् has author info.

Neither category nor author info is consistent. For example, the multiple versions of कादम्बरी, the prose romance by बाण and his son भूषणभट्ट, are spread across गद्यम् (prose — arguably most correct), पद्यम् (verse), and कथा (story). Similarly, the author name is recorded as "बाणः", "बाणभट्टः," and "बाणभट्टः भूषणभट्टः."

Search vs. Browse

The ebharatisampat.in website provides two ways to navigate: 1) a search bar, and 2) browsing with filters.

Search accepts one of seven metadata fields: BookName, BookId, Author, Publisher, Printer, Contributor, or Language. Results are displayed as thumbnail images along with a subset of metadata fields: serial number, title, author, category, and sub-category. The result list is flat and paginated, with a fixed ten items per page and no way to filter. The additional full-text search feature (Textual Search) is not discussed further here.

Note that metadata search uses substring matching, and it is apparently more forgiving if you use Devanāgarī. For example, searching for title "kādambarī" or "kadambari" (case-insensitive) turns up 13 items, while searching for "कादम्बरी" turns up 15, including one with the alternate spelling "Kadhambari". Similarly, "bāṇa" or "bana" gets 22 results, while "बाण" gets 25.

Browsing is accessed from the site's "Book Categories" menu, which offers "E-Books" (PDF), "Unicode Books" (proofread text) and "AI-converted books" (unproofread text).

Browsing results display as thumbnail images and titles (or as a list). Users can then narrow them by ticking values for any of the relevant metadata fields — categories, sub-categories, authors, publishers, contributors, and languages — and download a metadata spreadsheet for whatever is currently displayed.

Note that "E-Books," "Unicode Books," and "AI-converted books" are three distinct shelves, each showing one data type. They overlap: an item with both text and a PDF appears on two of them, so their counts add up to more than the number of items.

Sanskrit vs. Other Languages

Most E-bharatisampat material is in Sanskrit, with or without material in other languages. Going by the metadata, roughly a quarter of items pair Sanskrit with another language, most often Hindi or English, e.g., for introduction or facing translation. Strictly non-Sanskrit items comprise 3% of the total by item count.

These percentage numbers are computed after normalizing metadata inconsistencies. For example, "English" is written in four different ways, and one entry has "संस्कृतम" without halant/virāma.

In any case, this Atlas makes no attempt to control for language.

Obtaining and Representing E-bharatisampat Data

Scraping Metadata

All scraping for the Atlas is polite: one request at a time, at least 2 seconds apart.

The quickest way to a complete list of items is to walk the site's three shelves: "E-Books," "Unicode Books," and "AI-converted books." These return the most essential information directly: serial number, title, author, category and subcategory, plus publisher, contributor, and language, as well as a romanized title, which the Atlas uses for search but does not display. Proofreading status is determined by whether a searchable text appears on the "Unicode Books" or the "AI-converted books" shelf. Walking all three takes about 150 requests, or about 5 minutes.

The individual metadata pages remain the only source for the remaining fields (pages, publication year, printer, editors, commentators, translator) and for whether a text is flat or divided into chapters. Fetching every one takes one request per item, about 11,000 requests, or about 7 hours.

The vast majority of the Atlas is constructed on the basis of this metadata.

Calculating Size Information

Full texts are scraped only to measure their size; none is published, and PDFs are not fetched. Each text is a single page, so this takes about 5,600 requests, or about 6 hours. Pages are kept as delivered, so text can be re-extracted without refetching.

Size is measured in two steps:

  1. extract the text from the page (discarding 30% of its bytes), and
  2. transliterate Devanāgarī to IAST (a further 50% reduction in bytes).

Altogether: 9.9 GB of pages as delivered → 1.9 GB of IAST text, the sizes the Atlas reports.

Calculating Date Information

Item metadata contains no explicit time signals: no date added, no last-updated date. However, there are two implicit time signals: 1) serial numbers, and 2) a hidden timestamp in the filename of thumbnail images. On their own, neither of these could be conclusive. However, the fact that they strongly correlate with each other (Spearman ρ = 0.973) corroborates the value of both.

These correlated implicit signals allow us to do the following:

  1. Read serial number as relative order of addition.
  2. Take the vast majority of image file timestamps that monotonically increase with serial numbers as the specific date of addition.
  3. For the 207 timestamps that defy that order — 207 run more than a year ahead of their serial neighborhood, and 0 run more than a year behind — interpolate a synthetic date of likely addition from the serial neighborhood instead.

One natural reading of a late timestamp is that the item was changed then — that it is, in effect, a last-updated date. This is worth testing, because if true, we would have another time axis to work with.

There is exactly one way to test it from outside: a partial fulltext dump by Vishvas Vasuki, posted at sanskrit/raw_etexts and frozen at February 2025 (later commits are not consequential), holding 2,737 texts (24.4% of the catalogue). It lets the same books be read years apart.

The hypothetical last-updated interpretation does not survive scrutiny. Of the 3,318 items stamped after the 2025 dump was taken, 3,276 (98.7%) were simply not in it — new acquisitions, as a date-added reading predicts. Only 42 were present in 2025 and later restamped, and across 2,626 books present in both dumps, those restamped few are indistinguishable from the rest: 66.7% within ±2% of their 2025 length, against 70.4% of books whose timestamp never moved. Manual inspection suggests the only visible discrepancies boil down to global orthography normalization, likely by Vishvas himself.

So a late timestamp marks some later touch to the record, but nothing on the site says what, and the one external check finds no trace of anything meaningful in the text. This leaves us free to basically disregard out-of-order timestamps as noise.

In the Atlas, items are presented confidently with timestamps, and synthetically derived timestamps are marked as such with an asterisk and a tooltip explaining the estimate. Emphasis on Searchable Text over PDFs

This Atlas focuses on searchable text. That said, it does still have entries for items containing only PDFs on the source site. A "TXT only" toggle allows users to fully conceal these items from consideration if they wish. Note that PDFs are fully disregarded for the purpose of calculating collection size in megabytes.

For each item the Atlas displays, "PDF" and "text" tag links are provided as applicable.

Text items that have chapter-by-chapter structure also bear an inert tag "TOC" for "table of contents." Unproofread texts, which the site shelves as "AI-converted books," bear an inert tag "AI."

Browsing by Categories and Authors

The default view is a category tree. Within this, users can optionally choose to also group by author.

Alternatively, the tree can be inverted so that authors are primary and categories are secondary. No normalization is performed on author names, so the site's own divisions into e.g. कालिदासः and महाकविकालिदासः are retained here.

Category, sub-category, and author headers link to the source site's two navigation methods.

Browse links go to the site's shelves, filtered to that one value: "browse txt" for "Unicode Books," "browse AI" for "AI-converted books," and "browse PDF" for "E-Books." A link appears only if that shelf holds any of the header's items.

Search links ("search txt+pdf") show texts and PDFs together in one flat list. Search can filter by category or author but not by sub-category, so sub-categories get browse links only.

Groupings the Atlas itself introduces ("unknown" author, "uncategorized") get no links, because they are not values the site can filter by.
